# Data contracts add-on: what was added and what was changed

Apply by unzipping `fbl_contracts_addon.zip` over your project folder. It contains only NEW files and the CHANGED files listed
below, at their project paths. **Do not overwrite your `README.md`**: add the one line shown at the bottom instead.

## NEW files (nothing of yours is overwritten)

| File | Purpose |
| --- | --- |
| `contracts/source/fbl_source_{team,player,batting}.yaml` | Source (bronze) contracts: file shape, landing folder, arrival SLA |
| `contracts/silver/fbl_silver_{team,player,batting}.yaml` | Silver contracts: typed schema, every DQ rule with its action, standardization, lineage |
| `contracts/gold/fbl_gold_{dim_team,dim_player,fact_batting}.yaml` | Gold contracts: NULL-free schema, keys, assertions, freshness SLA, consumers |
| `contracts/semantic/fbl_semantic_{mv_fbl_batting,mv_fbl_roster}.yaml` | Semantic contracts for the FBL metric views (interface, formula fingerprints, reconcile/bounds tests, SLA) |
| `contracts/semantic/lahman_semantic_{mv_batting,mv_pitching,mv_team_season}.yaml` | Semantic contracts for the existing MLB metric views, with record-book golden values |
| `sql/fbl/metric_views/mv_fbl_batting.sql`, `mv_fbl_roster.sql` | The two new FBL metric views the semantic contracts govern |
| `src/lib/contracts.py` | Load, lint, compile (rules, typing SQL), bundle, diff, stamp. Pure Python |
| `src/lib/contract_checks.py` | Schema conformance for tables; interface, tests and SLA for metric views |
| `tools/contract_tool.py` | CLI: `lint`, `bundle`, `stamp`, `diff`, `export-rules` |
| `tests/test_contracts.py` | 20 static tests (lint, rule equivalence, diff policy, bundle, notebook freshness) |
| `.github/workflows/contracts.yml` | Automated lint, breaking-change gate and publish (not yet run against your workspace) |
| `docs/DATA_CONTRACTS.md` | Full guide, including manual and automated movement |
| `docs/CONTRACTS_CHANGELOG.md` | This file |

## CHANGED files (overwrite your copy)

| File | What changed |
| --- | --- |
| `src/lib/fbl_pipeline.py` | **Main change.** Added `load_registry`, `stage_contracts` (lint + publish + compile rules), `stage_semantic` (create metric views, run semantic contract checks). `stage_bronze` now takes expected columns and landing folder from the source contract and runs schema conformance. `stage_silver` generates the typing SELECT from the silver and source contracts and runs schema conformance. `stage_gold` runs schema conformance and takes its reconciliation table from the gold contract. `stage_setup`: `rules_csv_text` is now optional (CSV only seeds rules when you pass it); also creates the `semantic` schema, tables `data_contracts`, `data_contracts_history`, `contract_results`, and views `v_contract_status`, `v_contract_failures`. `build_report` adds a contract section and returns a new key `contract_failures`. Built-in definitions are kept as a fallback when no contracts are published. |
| `src/notebooks/fbl_dq_pipeline.py` | Regenerated by the builder. Now also inlines `contracts.py` and `contract_checks.py`, embeds a built-in contract bundle, and has new widgets: `rules_source` (contracts/csv), `include_semantic`, `contracts_dir`, and new `stage` values `contracts` and `semantic`. The final failure rule also fails on broken contract checks. |
| `resources/fbl_dq_pipeline.job.yml` | 5 tasks became 7: added `contracts_publish` (after `setup`) and `semantic_contracts` (after `gold_assert`); `report_and_notify` now depends on `semantic_contracts`. If you built the job in the UI, add those two tasks (`stage=contracts`, `stage=semantic`, same `catalog` and `run_id` parameters). |
| `tools/build_fbl_notebook.py` | Inlines the two new modules, embeds the contract bundle (needs PyYAML to build), strips all `from lib.x import` lines, new glue code. |
| `tests/check_fbl_pipeline.py` | Added `scenario_contracts` (contract run must match the built-in run exactly, semantic checks, three negative tests) and the local `MEASURE()` stand-in executor. The notebook scenario passes the new widgets. |
| `tests/test_fbl_static.py` | The job-graph test now expects the 7-task job. |
| `tests/local_pipeline_check.py` | Added `check_lahman_contracts`: runs the three Lahman semantic contracts against locally built gold tables. Nothing else changed. |
| `docs/DQ_PIPELINE.md` | Added a "Contract mode" note and the two new job tasks. |
| `docs/DQ_ANSWER_KEY.md` | Added "Contract mode: extra expectations" (including the expected P027 weight warning). |

## Behaviour changes to know about
1. **Rules now come from the contracts.** The notebook default is `rules_source = contracts`. Set it to `csv` to use `data/dq/dq_rules.csv` exactly as before.
2. **`governance.dq_rules` is overwritten** each time contracts are published (same 41 rules today). Edits you make directly to that table are replaced on the next publish; change the contract instead.
3. **Re-run `setup`** once in your existing environment to create the new tables and views (it uses `IF NOT EXISTS`, so it is safe).
4. **A broken contract fails the job**, in the same way a failed gate does. Interface type mismatches are warnings until you set `strictTypes: true`.
5. **New object created:** `semantic.mv_fbl_batting` and `semantic.mv_fbl_roster` (needs metric view support on your compute).
6. **Verification:** `pytest -q` (58 tests) and `python tests/check_fbl_pipeline.py`.
